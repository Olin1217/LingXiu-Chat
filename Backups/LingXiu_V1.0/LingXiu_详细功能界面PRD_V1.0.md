# 1. 产品概述

## 1.1 产品定位

“灵嗅（LingXiu）”是一款面向职场新人、社交经验不足用户及高频沟通人群的 AI 沟通决策助手。

用户可以上传聊天截图、粘贴聊天内容或手动描述事件。系统结合人物关系、沟通场景、上下文、表情、标点、语气、双方身份、历史互动和用户目标等信息，分析对方可能的表达意图，并根据用户选择的回应方向生成具体回复。

产品不宣称“看穿人心”，而是：

- 识别聊天中的沟通信号
- 推测多种可能意图
- 提醒关系风险
- 帮助用户选择回应策略
- 生成可直接复制的回复文字
- 逐步形成用户专属的人物关系档案

## 1.2 一句话介绍

> AI 帮你读懂话外之意，判断关系局势，并给出更合适的回应方式。

## 1.3 核心价值

传统 AI 工具主要解决“这句话怎么写”。

本产品解决完整的沟通决策链路：

```text
输入聊天内容
→ 识别人物与场景
→ 分析表达信号
→ 推测对方意图
→ 判断关系风险
→ 用户选择沟通目标
→ 生成多种回复
→ 记录反馈并更新人物角色卡
```

## 1.4 产品原则

1. **概率表达**：所有性格、态度和意图判断使用“可能、倾向、当前表现”等表达，不使用绝对定性。
2. **证据可见**：每项分析尽量说明依据，例如措辞、表情、回复速度、上下文或权力关系。
3. **用户掌握决策权**：AI 提供建议，不替用户自动发送消息，不擅自决定接受或拒绝。
4. **结果导向**：用户先选择想达到的结果，再生成对应回复。
5. **隐私优先**：支持截图打码、自动模糊头像昵称、删除记录和无痕分析。

# 2. 目标用户

## 2.1 核心用户

### A. 职场新人

典型需求：

- 不知道如何回复领导
- 不理解模糊反馈
- 不知道什么时候解释、接受或拒绝
- 害怕显得情商低或执行力差

### B. 社交经验不足用户

典型需求：

- 不理解别人话里的含义
- 无法判断对方是真诚、客套还是试探
- 不知道如何保持距离
- 容易过度解读或完全忽略暗示

### C. 商务、销售与客户沟通用户

典型需求：

- 判断客户真实兴趣
- 识别压价、拖延或婉拒
- 生成谈判、催进度、维护关系的话术
- 保留证据并跟踪人物关系

### D. 情感与家庭关系用户

典型需求：

- 判断情绪变化
- 识别冷淡、委屈、试探或求关注
- 处理误会、拒绝和边界问题
- 避免错误回复引发进一步冲突

## 2.2 首发用户范围

MVP 优先聚焦：

> 22—35 岁职场用户，尤其是刚毕业、刚入职、换领导、跨部门协作和客户沟通人群。

原因：

- 沟通频率高
- 使用场景明确
- 截图输入习惯成熟
- 付费意愿高于泛社交用户
- 内容传播性较强

# 3. 核心使用场景

## 3.1 回复领导

用户上传领导消息，系统分析：

- 领导是在提醒、否定、施压还是要求行动
- 对方更关注结果、态度还是时间
- 用户适合接受、解释、争取时间或询问方向

## 3.2 婉拒请求

用户选择：

- 明确拒绝
- 委婉拒绝
- 保留后续可能
- 提供替代方案
- 不伤害关系

系统生成不同强度的话术。

## 3.3 客户沟通

系统帮助判断：

- 客户是真有兴趣还是礼貌回应
- 是否在压价
- 是否在拖延决策
- 当前适合跟进、让步还是暂停打扰

## 3.4 情绪沟通

系统结合文字、表情和上下文分析：

- 对方是否可能有情绪
- 是否存在反话、敷衍或求关注
- 用户适合安抚、解释、道歉还是保持距离

## 3.5 长期人物关系跟踪

用户为领导、同事、客户、亲人等创建人物角色卡。

后续每次分析可关联角色卡，AI 根据历史互动逐渐总结：

- 沟通风格
- 关注重点
- 常见表达方式
- 高风险雷区
- 推荐沟通策略

# 5. 全局 UI 设计原则

## 5.1 视觉方向

关键词：

- 克制
- 可信
- 温和
- 专业
- 非娱乐化
- 非“算命感”
- 非夸张心理诊断

建议视觉：

- 浅色背景
- 低饱和蓝灰、米白或墨绿色作为主色
- 重点信息使用卡片分组
- 概率与风险信息使用分级标签
- 尽量减少大面积渐变和夸张光效

## 5.2 组件规范

### 主按钮

- 高度：48–52 pt
- 圆角：12–14 pt
- 文案：动作明确，例如“开始分析”“生成回复”
- 页面底部可使用吸底按钮

### 次按钮

- 描边或浅底
- 用于“稍后补充”“重新选择”“跳过”

### 标签

用于：

- 人物关系
- 场景
- 沟通类型
- 风险等级
- 回复风格

### 信息卡片

结构：

```text
标题
简短结论
证据或说明
可展开详情
```

### 置信度

不建议直接展示“AI 判断正确率”。

建议展示：

- 高可能
- 中等可能
- 低可能
- 信息不足

可在详情中展示百分比，但必须说明是推测范围。

# 11. 分析结果页

## 11.1 页面名称

> 沟通分析

## 11.2 页面总览区

顶部展示：

- 人物头像 / 角色图标
- 人物名称
- 关系标签
- 场景标签
- 分析时间

核心结论：

> 对方更可能是在表达对结果的不满意，同时希望你主动提出下一步方案。

说明：

> 以下内容为基于当前信息的可能性分析，不代表对方真实心理的确定结论。

## 11.3 模块一：这句话怎么理解

标题：

> 话外之意

内容结构：

### 表层意思

> 希望你继续优化方案。

### 可能的真实关注

1. 结果没有达到预期
2. 希望你主动发现问题
3. 不希望重复解释过程
4. 期待明确的修改时间

### 其他可能

折叠区域：

- 可能只是常规反馈
- 可能没有强烈负面情绪
- 可能受当时场合影响

## 11.4 模块二：沟通信号

标题：

> AI 注意到的信号

分析维度：

### 用词

> “再看看”比“重新做”更委婉，说明对方可能希望保留调整空间。

### 标点

> 连续使用句号，语气可能更正式或更冷静，但不能仅凭标点判断情绪。

### 表情

> 使用“微笑”表情可能表示礼貌、缓和或轻微距离感，需要结合上下文判断。

### 回复节奏

> 对方在较长间隔后只回复一句，可能表示忙碌、兴趣下降或希望结束当前话题。

### 场合

> 发生在群聊中，对方可能更重视公开态度，而不是详细讨论。

### 权力关系

> 对方是直属领导，因此模糊表达可能包含任务要求，而不只是意见建议。

每个维度支持：

- 展开证据
- 标记“不准确”
- 用户补充说明

## 11.5 模块三：对方当前沟通画像

标题：

> 当前沟通特点

说明：

> 以下是基于本次和历史互动总结的沟通倾向。

维度标签：

- 结果导向
- 表达直接
- 偏好简洁
- 重视反馈
- 习惯暗示
- 情绪敏感
- 边界感强
- 决策谨慎

展示结构：

```text
主要倾向：结果导向
表现依据：多次要求明确时间和产出
建议：回复时优先给行动和时间点
```

注意：

不得使用疾病诊断、人格障碍、操控型人格等未经验证的标签。

## 11.6 模块四：他可能想从你这里获得什么

标题：

> 对方可能期待

可展示：

- 明确答复
- 立即行动
- 情绪安抚
- 尊重与认可
- 资源支持
- 让步
- 承担责任
- 保持联系
- 证明诚意
- 获取信息

# 24. AI 分析逻辑

## 24.1 输入结构

系统向模型提供：

```json
{
  "conversation": [],
  "user_role": "",
  "other_person_role": "",
  "relationship_type": "",
  "relationship_stage": "",
  "scene": [],
  "power_relation": "",
  "response_timing": "",
  "known_person_profile": {},
  "user_goal": "",
  "tone_preferences": {}
}
```

## 24.2 输出结构

```json
{
  "summary": "",
  "surface_meaning": "",
  "possible_intentions": [
    {
      "label": "",
      "likelihood": "high|medium|low",
      "evidence": []
    }
  ],
  "communication_signals": [],
  "possible_expectations": [],
  "relationship_state": {},
  "risks": [],
  "recommended_actions": [],
  "reply_options": []
}
```

## 24.3 分析维度

系统至少考虑：

1. 原始文字
2. 上下文
3. 说话人身份
4. 双方权力关系
5. 沟通场合
6. 标点
7. 表情
8. 回复速度
9. 语气变化
10. 历史互动
11. 用户补充信息
12. 用户目标

## 24.4 置信度规则

- 信息充分：给出主要可能与次要可能
- 信息一般：明确提示存在多种解释
- 信息不足：优先追问，不做强结论
- 高风险场景：建议用户核实现实信息

# 30. 产品核心结论

“灵嗅（LingXiu）”不应被做成一个普通的 AI 文案生成器。

它的核心差异化应当是：

```text
人物角色卡
+
模板化背景输入
+
多维沟通信号分析
+
用户回应目标选择
+
分层回复策略
+
长期关系记忆
```

第一版最重要的不是覆盖所有社交关系，而是把“回复领导、拒绝请求、客户沟通”三个高频场景做得足够准确、可信和容易使用。

产品最终目标：

> 成为用户身边长期使用的 AI 人际沟通顾问，而不是一次性的聊天回复工具。
